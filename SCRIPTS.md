# Setup Scripts

## Entry point and prerequisites

Run `./install-all.sh` on a fresh Omarchy installation to install the applications and managed desktop configuration, then link the separate dotfiles repository. Bash is required; package installation needs network access and may request elevated privileges. Run as the normal desktop user, not root.

Clone the dotfiles repository alongside this one at `../dotfiles` before running setup. It supplies the `nvim`, `starship`, `tmux`, and `zsh` Stow packages. This repository does not duplicate those configurations.

## Installers and shared helpers

- **`install-monitor-layout.sh`** — Runs last in `install-all.sh`, after feature installers. Requires Python 3; an active Hyprland session with connected displays is needed to resolve plugin connector targets. Deploys the central `monitor-layout.json`, monitor resolver, description-based monitor/workspace rules, span/single-monitor helpers, and rendered Shibumi bar filters. Updates only configured widget targets, wallpaper span groups, and lock main/side/span assignments; preserves credentials, wallpaper choices/stopped state and edited lock timeouts/tints. Creates System Metrics' screen configuration only if its plugin is installed. Backs up changed files under `~/.local/state/arch-setups/backups/monitor-layout-<timestamp>/`, writes atomically, and prints `already installed` when current. Reloads/validates Hyprland when connected; reapplies Wallpaper Controller only when its span changes. Missing displays preserve existing plugin targets. Change identities and feature assignments in the repository-root `monitor-layout.json`, then rerun this installer after changing ports. Disable features through their individual controls; this script enables no plugin.

**Display policy:** `main` is the Microstep OLED; `side_left` and `side_right` are the two Lenovo descriptions including distinct serials. Current connectors DP-6/DP-5/DP-4 are discovered values. `windowSpan`, `singleMonitorKeep`/`singleMonitorDisable`, `barMain`, `wallpaperSpan`, `lockMain`/`lockSides`, and `widgetTargets` are editable in one file. Geometry stays in hyprmoncfg's identity-based profiles, with `hypr/monitors.lua` as the managed fallback. Shibumi and shortcuts match stable descriptions; connector-only plugin configurations need this installer rerun after port changes.

- **`install-all.sh`** — Runs the explicitly listed installers in order, including Wallpaper Controller after the managed Hyprland configuration, then Shibumi Shell and its dependent Per-monitor Workspaces feature, before `install-dotfiles.sh`. Provides the single setup command and stops on a failed installer. Shibumi’s default activation replaces the active bar and restarts the Omarchy shell.
- **`lib.sh`** — Shared logging, `monitor_layout_render` for identity-based Lua/QML templates, executable detection, desktop-file detection, Omarchy availability checks, backup and pinned git checkout helpers, feature-profile state checks, and `install_mise_cli` for protocol-safe CLI wrappers. The mise helper requires an existing mise executable, checks `mise which` and installs/configures a missing tool through `mise use -g` only when needed; deploys wrappers under `~/.local/bin/`, backs up replaced known files under `${XDG_STATE_HOME:-~/.local/state}/arch-setups/backups/<tool>-mise-<timestamp>-<pid>/`, and preserves unknown custom wrappers/symlinks. Matching tool/wrapper state prints `already installed` and exits 0. Sourced by installers to avoid duplicating these helpers; not an installer itself.
- **`config/feature-profile.py`** — Helper script to query and persist feature enable/disable choices in `~/.local/state/arch-setups/features.json` against repository defaults in `features.json`. Supports `enabled`, `remember`, and `export` commands.
- **`install-chrome.sh`** — Installs Chrome through `omarchy install browser chrome` if its executable or desktop file is absent. Provides the Chrome browser.
- **`install-brave-origin.sh`** — Installs Brave Origin through `omarchy install browser brave-origin` if its executable or desktop file is absent. Provides the Brave Origin browser.
- **`install-zen.sh`** — Installs Zen through `omarchy install browser zen` if its executable or desktop file is absent. Provides the Zen browser.

- **`install-codex.sh`** — Ensures mise-managed Codex is available using `lib.sh`'s `install_mise_cli`, and deploys `t3/codex` to `~/.local/bin/codex`. Requires Bash/coreutils and mise; network access is needed only when mise must install/update the tool. Replaces only the exact known noisy mise wrapper (or a matching managed wrapper missing execute permission), backing it up first; unknown custom wrappers/symlinks are preserved. The wrapper preserves the original `MISE_MINIMUM_RELEASE_AGE=0`, `mise use -g "codex"` preparation and `mise x "codex" -- "codex" "$@"` launch behavior, but sends preparation's stdout to stderr. Actual Codex stdout/arguments/exit status are untouched, so app-server's JSON protocol stays clean without bypassing mise. Matching installation prints `already installed` and exits 0. No Arch Codex package is installed/removed; authentication, sessions and dotfiles remain untouched.
- **`install-github-cli.sh`** — Ensures mise-managed `gh` is available and deploys `github/gh` to `~/.local/bin/gh` through the same shared helper. Requires Bash/coreutils and mise, with network access for missing tools. Replaces only the exact known noisy mise wrapper or this repository's earlier `/usr/bin/gh` wrapper, with a backup; custom wrappers/symlinks are preserved. Like Codex, the wrapper retains `MISE_MINIMUM_RELEASE_AGE=0` and `mise use -g "gh"`, redirecting only preparation's stdout to stderr before `mise x "gh" -- "gh" "$@"`. T3 and terminal commands use mise's selected version rather than the Arch package, while `gh auth status --json hosts` remains valid JSON. This fixes “Could not verify GitHub” without suppressing errors. Existing GitHub credentials and system packages are preserved. Matching installation prints `already installed` and exits 0. Refresh T3's GitHub check after running. Wrapper preparation may install/update tools and modify mise's global tool entries as the original wrappers did; unrelated mise settings are not edited. Restore a backup and remove the installer registration/dependency to undo managed deployment. Tests covering both installers/wrappers (with a fake mise, no downloads): `python3 -m unittest discover -s github -p 'test_*.py'`.
- **`install-t3code.sh`** — Installs stable `t3code-bin` through Omarchy only if neither stable nor nightly is available, prepares the mise-backed wrappers through `install-codex.sh` and `install-github-cli.sh`, then runs `t3/configure-codex.py`. Registered in `install-all.sh` after Codex and GitHub CLI. Requires Python 3 and mise; Omarchy/network/privileges are needed only for missing T3. Manages `${T3CODE_HOME:-~/.t3}/userdata/settings.json`: existing-install Codex default paths (empty, `codex`, `~/.local/bin/codex`, or the earlier `/usr/bin/codex` fix) become `codex`, so T3 uses the protocol-safe mise wrapper via PATH, just like the terminal. Ensure `~/.local/bin` precedes system/mise executable directories in T3's environment; the separate Zsh dotfiles already prioritize this directory for terminals. Custom paths, managed Codex instances, enabled/disabled state, authentication paths, launch arguments, other providers and unrelated settings are preserved. Seeds a default Codex instance only if none exists. Matching software/config prints `already installed` and exits 0. Backs up changed settings as `settings.json.bak-codex-path-<UTC timestamp>` and writes atomically, refusing malformed JSON or an intervening edit. T3 watches the settings file; refresh providers or reopen T3 if the old error remains. Does not remove/switch nightly, alter desktop profiles, or migrate databases/projects/sessions. To opt out, choose a custom absolute Codex path in T3 (paths other than the listed managed defaults are preserved). Tests: `python3 -m unittest discover -s t3 -p 'test_*.py'`.

Deploys the CLI launcher helper to `~/.local/bin/t3-planner-executor`. State management uses Linux `util-linux`/`flock` transaction locks and unique atomic temporary files (`<statefile>.<pid>.<uuid>.tmp`) to protect concurrent ledger updates; the helper uses verified standalone Node.js on PATH (or `T3_STATE_NODE_BINARY`) instead of compiled harness executables, with bounded verification and distinct startup/lock contention errors. Fully quit and reopen T3 Code when idle after updating so existing provider processes load the corrected module. Detects genuinely available providers: discovers the native Antigravity binary pair (`agy_acp_server.par` and `localharness_external`) via active managed tools under `~/.t3/tools/antigravity-acp/<platform>-<arch>/active.json` or existing descriptors, reporting pending setup instructions if absent without fabricating binaries. The current check compares pinned source revision, exact byte-for-byte runtime files, executable modes, symlinks, valid JSON shape, exact Pi extension arguments in `settings.json`, and native Antigravity descriptors. Matching state prints `already installed` and exits 0 without network access or file rewrites. `--enable` activates the workflow; `--disable` sets `enabled: false` and remembers the choice across `install-all.sh`; `--remove` preflights settings, safely unconfigures T3 provider settings and aliases (restoring verified backend paths), removes the launcher symlink, archives all managed runtime files, settings, and descriptors under `~/.local/state/arch-setups/backups/t3-planner-executor-remove-<timestamp>/`, and unlinks only owned runtime files while preserving custom manual files, local workflow state, and personal config. Historical backups, vendor binaries (`~/.t3/tools`), and authentication are preserved. Tests: `python3 -m unittest discover -s tests -p 'test_t3_planner_executor.py'`.

Installs Steam and Gamescope through `omarchy pkg add`, deploys the `steam-gamescope-hdr` launch wrapper to `~/.local/bin/steam-gamescope-hdr` with `ENABLE_HDR_WSI=1`, `DXVK_HDR=1`, and Gamescope HDR with explicit game-visible and output dimensions of `3840×2160`, fullscreen, and `--force-windows-fullscreen`. Idempotently configures installed Steam games in `localconfig.vdf` across user profiles and Windows game shortcuts in `shortcuts.vdf`, preserving environment variables and game arguments. Existing direct Gamescope commands get matching 4K dimensions without a nested compositor; obsolete Gamescope FSR spatial-upscaling flags are removed. Close Steam before running: the configurator refuses live edits to prevent Steam overwriting them and backs up changed VDF files alongside the originals as `*.bak-4k-<timestamp>`. Native utility shortcuts and Wallpaper Engine are excluded. New games require rerunning the installer. For an existing `HaloCampaignEvolved.exe` shortcut, adds a missing Proton Experimental compatibility mapping to Steam's `config/config.vdf` (backed up), preserving any user-selected tool; install Proton Experimental through Steam before launching. This avoids Linux attempting to execute the Windows binary directly. In-game resolution/upscaling settings may still need adjustment; this guarantees a 4K virtual display, not every engine's internal rendering resolution. Regression checks: `python3 -m unittest discover -s steam -p 'test_*.py'`. Exits early when Steam, Gamescope, the wrapper, and game launch configurations are already current.

## Hyprland runtime helpers

- **`hypr/scripts/shell-recover.sh`** — Deployed by `install-hyprland.sh` and called by `hypr/autostart.lua` on `config.reloaded`. Checks Omarchy shell IPC and uses `omarchy restart shell` only if unavailable; a runtime `flock` prevents concurrent recoveries. Requires Omarchy, util-linux, and an active Hyprland session. Preserves the stock restart command's lock-screen protections. Does not restart a healthy shell. After watchdog recovery, old terminals can retain a stale compositor address: use `hyprctl -i 0 reload` for the sole live instance or a new terminal. Remove the reload hook to disable recovery.

These are deployed by `install-hyprland.sh`, not run as installers:

- **`hypr/scripts/monitor-mode-toggle.sh`** — Bound to `Super+Shift+M`. Uses `singleMonitorKeep`/`singleMonitorDisable` in the deployed policy; verifies the kept display is available before disabling anything. Writes stable description selectors to `~/.local/state/omarchy/toggles/hypr/desktop-single-monitor.lua` and applies them live. Switching back removes that toggle and its legacy `.conf`, reloads Hyprland, and restores Wallpaper Controller. Requires Hyprland, Python 3 and `notify-send`. Applying a hyprmoncfg profile can override these rules; reapply the toggle after profile changes.
- **`hypr/scripts/window-span-dp6-dp4-toggle.sh`** — Bound to `Super+Ctrl+Shift+F`. The historical filename/state path are retained to allow restoring already-spanned windows. Reads `windowSpan` roles through the deployed monitor resolver, temporarily floats/resizes/pins the active window across their live logical canvas, then restores its saved state on the next invocation. Accounts for rotation, scale and reversed screen order; rejects missing/disabled displays, gaps and mismatched heights with a useful error before modifying the window. Requires Hyprland, Python 3 and `jq`, with optional notifications. State remains under `${XDG_STATE_HOME:-$HOME/.local/state}/omarchy/window-span-dp6-dp4/`; restoration works even if the selected monitors are disconnected.
- **`hypr/scripts/monitor-layout.py`** — Shared display-policy implementation, deployed to `~/.config/hypr/scripts/` along with `~/.config/omarchy/monitor-layout.json`. `resolve` reports role-to-connector mappings, `canvas` validates live window-span geometry, `single-monitor-lua` generates safe description-based disable rules, `render` fills monitor/QML selectors from the repository policy, `configure-widget` applies one widget target during standalone installation, and `install` applies the managed files and existing plugin configurations with backups. Python 3 standard library only. `install-hyprland.sh` invokes `install --hypr-only` for the core display files; `install-monitor-layout.sh` also handles plugin targets. Regression tests: `python3 -m unittest discover -s tests -v`.

- **`hypr/scripts/bar-visibility-mode-toggle.sh`** — Bound to `Super+Shift+Space`. Cycles top bar visibility mode through Always show, Auto-hide, and Disabled by toggling state files under `~/.local/state/omarchy/toggles/` (`bar-autohide` and `bar-off`) and emitting desktop notifications.
