# Scripts

## Setup contract and quick start

Run as the normal desktop user on Omarchy 4.0.4+ (not root). Bash, Python 3, Git, coreutils, diffutils/cmp, util-linux/flock and network access for missing packages/sources are prerequisites. Desktop features additionally require a live, **unlocked** Omarchy/Hyprland session. Package and source compatibility is revision-bound; a version minimum alone is not runtime acceptance.

```bash
./install-all.sh --plan                           # strictly read-only
./install-all.sh                                  # safe applications; no games/private widgets
./install-all.sh --profile personal --host profiles/laptop.json \
  --dotfiles-dir /path/to/dotfiles --plan
```

`features.json` is the safe default; `profiles/personal.json` selects the fuller desktop preset. Use a custom profile to select only what you want. Successful explicit plugin install/disable/remove commands remember choices under `${XDG_STATE_HOME:-~/.local/state}/arch-setups/features.json`; remembered choices override the profile. `--ignore-local-choices` previews/applies the profile without those overrides. Skipping an installer does not uninstall software already on the machine; use its lifecycle command to disable existing behavior.

Fresh ISOs can ship only an offline package index. Apply requests confirmation before initial Omarchy snapshot/keyring/full system-package upgrade/migration/post-update-hook stages; `--approve-system-update` explicitly authorizes that bootstrap for automation. It never performs only `pacman -Sy`, invokes the interactive reboot picker, runs separate AUR/mise update stages, or removes orphans. A failed/interrupted bootstrap is recorded privately and must be retried with approval before any installers. Exit **3** requests reboot/login and a rerun. Already-indexed systems with no recovery marker skip this step. Standalone installers assume package indexes/platform prerequisites are initialized; the single entrypoint coordinates this preparation.

Additional inputs: `--host FILE` (monitor policy), `--games FILE` (opt-in game selection), `--settings FILE` (local widget configuration/credential-file references), `--planner-config FILE` (workflow provider/model seed), and `--dotfiles-dir DIR`. Equivalent variables are `ARCH_SETUPS_PROFILE`, `ARCH_SETUPS_MONITOR_LAYOUT`, `ARCH_SETUPS_GAMING_PROFILE`, `ARCH_SETUPS_SETTINGS`, `T3_PLANNER_EXECUTOR_SEED_CONFIG`, and `ARCH_SETUPS_DOTFILES_DIR`. See [README.md](README.md) and the examples in `profiles/`.

No script invents credentials, enrolls accounts, formats/mounts game drives, downloads games, or duplicates the separate dotfiles configuration. Supply/authenticate external prerequisites first. An apply run fails early for missing required tools, dotfiles or source access, stops on an installer failure, and finally checks selected features. Doctor acceptance exits **1** on errors or **2** on pending integrations/missing optional game data; neither is “everything ready.” Pairing, remote service connectivity and physical desktop acceptance remain explicit manual checks.

## Entrypoint, diagnostics and shared helpers

- **`install-all.sh`** — Explicit, dependency-ordered installer list; resolves validated feature selection before running anything. `--plan` prints selected/skipped steps and game changes without installation, networking or state writes. Apply rejects root, runs preflight, holds an install lock, confirms any required initial package preparation and revalidates afterward, skips disabled features/dependents, stops on failure, then runs doctor acceptance. `--approve-system-update` approves only required initial preparation/recovery, not routine upgrades. It never silently updates source pins. Re-run after fixing a prerequisite; successful installers reconcile their owned state.
- **`preflight.sh`** — Read-only wrapper around `config/doctor.py --preflight`. Validates profile/host/game/settings inputs, selected dotfiles/tool prerequisites, unlocked session for desktop features, and Git access using each selected source's transport. Exact clean local checkouts need no network check; other sources use noninteractive, bounded Git access. It does not treat GitHub CLI login as proof of SSH access.
- **`doctor.sh`** — Read-only wrapper around `config/doctor.py`. Supports `--json`, `--acceptance`, `--profile FILE`, `--dotfiles DIR`, and `--export-profile`. Checks selected executables, plugin pin/origin/cleanliness/enabled state, suite status, credential permissions, local integration prerequisites, game/runner availability, selected services and Hyprland errors. Does not log secret values or claim remote API/hardware acceptance from file existence.
- **`lib.sh`** — Shared logging/application detection, Omarchy requirement, private backups, exact clean Git/source checks, staged pinned checkout installation, owned helper-link management and mise CLI deployment. Direct plugin lifecycle execution is wrapped so independent installer cleanup/rollback traps cannot suppress successful-only remembered choices. Feature state writes are locked and atomic; invalid profiles fail closed. Desktop-entry detection verifies its executable instead of accepting a stale launcher as installed software. Known legacy Codex/GitHub wrappers (including the pristine Omarchy 4.0.6 `mise use -g --quiet` templates) are privately backed up and migrated; custom code is preserved.
- **`config/feature-profile.py`** — Validates registered installer names/schema, resolves dependencies, prints a plan or selected list, remembers explicit choices and exports the resolved profile. Registry: `config/features.json`; source lock: `config/plugin-sources.json`. Tests check registration, ordering and source-lock/installer agreement. Unknown keys/names and malformed state are errors.
- **`config/setup-inputs.py`** — Validates optional host/game/widget inputs and prints a secret-free game plan. `widget NAME` seeds/updates supplied widget keys with locking, private atomic files, conflict checks and backups, preserving unrelated existing settings. Secret values come only from user-only `tokenFile`/`apiKeyFile` references; they are materialized into private runtime configuration, never committed or printed. HA retains its `tokenFile` reference instead of inlining the token. Explicit references are validated before apply. HA URL/entity defaults are portable blanks, not the backend's historical personal data.
- **`config/package-bootstrap.py`** — Entrypoint coordinator for missing/empty configured repository indexes (an ISO `offline.db` does not count). Uses Omarchy's update lock when available, snapshot, keyring, complete system-package upgrade, migration and post-update-hook commands; never invokes the restart picker. No setup software runs between keyring refresh and the full package upgrade. Private atomic `initial-system-update.json` recovery state prevents an interrupted update being mistaken for readiness just because indexes appeared. Checks new-kernel/deleted-Hyprland/Omarchy restart requirements and resumes after the required restart. Status/plan is read-only; apply requires interactive confirmation or explicit approval.
- **`config/managed-config.py`** — Comment-preserving JSONC menu edits. Removes only owned keys, validates results and uses private backups, a configuration lock, atomic replacement and intervening-edit checks. Wallpaper removal uses this helper, including for multiline entries.
- **`config/bar-layout.py`** and **`indicators/layout.py`** — Reversible owned bar-layout changes; preserve unrelated layout/settings and restore only still-owned values on disable. The common bar helper coordinates setup writes through the configuration lock.
- **`config/shibumi-settings.py`** — Changes supported Shibumi configuration: main-display identity, Bluetooth slot, native media-slot presentation and an explicit hidden suite media-service entry required by the center notch. `--media-backend-only` reconciles only that service demand, preserving current presentation. Preserves layout/payload and uses guarded atomic configuration writes. It does not copy QML into the suite.
- **`config/check-source-contracts.py`** — Bounded network check of the exact public Shibumi CLI and Omaland manifest APIs required by the installers. Reads source as data, never executes it or advances pins. Private source/API, live runtime and physical compatibility checks remain separate.
- **`tests/run.py`** — Clean-checkout test runner. Core tests are independent of the private Planner-Executor source. `--require-integration --integration-source DIR` requires its exact clean pinned Git checkout and runs those tests too; a missing/mismatched source fails explicitly. `--require-system-tests` fails on skipped system-library tests. GitHub Actions setup jobs have been removed. For manual checks, install Arch test dependencies (including GNU Stow and diffutils/cmp) and run unprivileged; private release integration requires authorized source access.

## Application installers

These scripts check whether the application is present before package installation. Existing healthy software is not reinstalled; owned configuration may still be reconciled. Missing packages use Omarchy and may request privileges.

- **`install-chrome.sh`** — Installs Chrome with `omarchy install browser chrome` when no healthy launcher/command exists.
- **`install-brave-origin.sh`** — Installs Brave Origin with Omarchy's browser installer; accepts its existing stable/beta installation.
- **`install-zen.sh`** — Installs Zen with Omarchy's browser installer when missing.
- **`install-stow.sh`** — Installs GNU Stow through `omarchy pkg add stow`; needed by dotfiles.
- **`install-hermes-desktop.sh`** — Installs Hermes Desktop through Omarchy when its launcher, command and package are absent.
- **`install-codex.sh`** — Ensures a mise-managed Codex executable and the owned `t3/codex` wrapper. Only installation may run `mise use -g`; normal wrapper execution uses read-only `mise which`, checks for recursion and preserves protocol stdout/arguments/exit status. Run the installer explicitly to repair a missing backend; custom wrappers are preserved.
- **`install-github-cli.sh`** — Same deployment model for mise-managed GitHub CLI and `github/gh`. Does not authenticate an account or configure Git credentials. Before private HTTPS source installation, perform authorized `gh auth login` and `gh auth setup-git`; SSH sources additionally require keys and verified host trust. Runtime `gh` does not auto-install/update tools.
- **`install-t3code.sh`** — Installs stable `t3code-bin` only when stable/nightly is absent; prepares Codex/GitHub helpers and uses `t3/configure-codex.py` for guarded, backed-up settings reconciliation. Preserves selected nightly, custom provider paths, unrelated settings and authentication.
- **`install-t3-planner-executor.sh`** — Optional private-source workflow adapter, pin `7ab9c0dd9774a75ee814a49ef41b281a03e96c36` from `git@github.com:priyeshbhawsar15/t3-planner-executor.git`. Requires Git, Python, Node.js, flock and its configured executor CLI (Pi by default); preflight reports missing tools before the full run and derives the executor from the selected config/seed. `--planner-config FILE`/`T3_PLANNER_EXECUTOR_SEED_CONFIG` selects external provider/model seed data; malformed seeds fail before source/runtime mutations. Supports the documented source/runtime/settings/helper overrides. Installs exact source/runtime files, safely seeds absent configuration, detects actual providers, and preserves explicit operator settings. `--enable`, `--disable`, `--remove` manage workflow state; removal preflights, privately archives original files, unconfigures only owned settings and preserves custom files/authentication. See `PLUGINS.md` for detailed controls. Not selected by the safe base.
- **`install-steam.sh`** — Installs Steam and configures silent desktop-login startup via `steam/configure-autostart.py` (`~/.config/autostart/steam.desktop`, main `Exec=/usr/bin/steam -silent`). Existing entries are backed up; unrelated fields/action commands are preserved, known disabled-entry flags are enabled, and custom commands/symlinks are refused. `--background-startup-only` applies just this configuration without restarting Steam or installing packages. Requires the desktop session's XDG autostart support (Omarchy's graphical session); no second startup mechanism is added. Disable login startup through Steam's startup setting; a later installer run intentionally reenables this managed preference. Interactive menu launchers remain unchanged. Does not change game launch options or HDR by default; automatically removes the retired 80% UI override while preserving other user-selected scaling. `steamHdr: true` in the gaming selection explicitly opts into broad Steam HDR launch wrapping; selected per-game HDR also requests Gamescope and the owned `steam/gamescope-hdr` helper, but does not rewrite all Steam games. The helper uses profile dimensions or the focused output, not universal 4K. Halo's selected HDR profile retains upstream `HALO_GAMESCOPE_CAPTURE=1`/`--force-grab-cursor` support; setting the helper's environment flag to `0` disables that capture override. Other games keep normal capture. Existing explicit Gamescope flags are preserved. Unknown helper files/symlinks are refused. Both `--ui-scale-only` (legacy alias) and `--ui-scale-reset` now only REMOVE the retired override through `steam/configure-ui-scale.py`; no code path installs 80% scaling. The helper strips known launcher overrides and removes only saved values approximately 0.8 at Steam's desktop-accessibility and Big Picture display VDF paths, preserving unrelated settings/action URLs. Persisted VDF changes require Steam closed; changed files are backed up and atomically replaced. Normal installation also performs this cleanup, so later setup runs cannot restore the old fix. Close Steam before opted-in VDF edits; modified VDFs are backed up and replaced atomically. No automatic game-launcher sync timer is installed.
- **`install-lutris.sh`** — Installs Lutris independently of library import and games. Without a selected/remembered Steam-first export, empty selection changes no library/database/game files and creates no personal account/webapp launchers. `--export-steam` explicitly runs `steam/export-lutris-steam.py --apply --enable --artwork`: it makes Steam the library frontend, retains Lutris as the configured backend, enriches available shortcut artwork/titles/icons, creates Steam-backed Omarchy launchers, hides recognized old Lutris game entries while keeping the Lutris application visible, and remembers the preference for future single-script reconciliation. Requires both clients closed; private backups protect changed VDF/desktop/menu files; missing source executables/artwork are reported. `exportSteam: true` in the gaming selection also opts into reconciliation; reverse-import loops are refused. `steam/metadata-policy.json` permanently excludes Sims 4/KS/HS2 visual metadata and removes the uninstalled HS2 shortcut/launcher; owned artwork is removed only when its SHA256 still matches and is backed up first. `steam/launcher-policy.json` keeps Lutris visible and retires recognized AoE account launchers/deduplicates app 813780 against its canonical Steam-backed entry. `steam/export-lutris-steam.py --apply --launchers-only` applies only those local launcher changes while Steam remains open; removed/changed files are privately backed up and no accounts, game data or Steam library entries are removed. See [Steam-first library](steam/STEAM-LIBRARY.md). `importSteam: true` opts into generic Steam import; selected direct profiles initialize the database without importing everything. `steam/gaming_profile.py` resolves chosen catalog templates from configured library roots and user choices. Uses Lutris's actual settings for legacy/new configuration layouts and custom database paths; positively selected misplaced legacy files are archived. Missing games are skipped without suppressing valid generic imports. Artwork and experimental upscalers are separate per-game opt-ins. 7zip is installed only for selected upscalers; downloads are exact/SHA256 checked. Foreign/modified mod files are refused unless the game explicitly opts into `allowModReplacement`; owned hashes and backups support recovery. Private configuration ownership records remove unchanged owned HDR fields on opt-out; omitting games/mods does not automatically uninstall prior DLLs. Halo's catalog defaults to separately installed `GE-Proton11-7-x86_64` to address a logged Experimental GStreamer/libav load failure (`libavfilter.so.7` missing) and suspected black cutscenes; playback verification remains pending. `wineVersion` overrides this runner without replacing saves/prefixes. The opt-in gaming example also documents Death Stranding 2 with HDR and explicit `[3840, 2160]` Gamescope dimensions; select matching resolution in-game separately. For selected Halo with an explicit `resolution`, the existing Meteorite INI receives those dimensions and borderless mode; `hdr: true` additionally manages its HDR output flag and Proton HDR environment. No resolution selection leaves that INI untouched. Original encoding, line endings, unrelated sections and backups are preserved; missing/ambiguous sections and symlinked INIs are refused. Engine settings already applied require deliberate backup restoration on opt-out. No implicit retirements, fixed accounts or game-drive symlinks. Close Lutris/affected games first. See `steam/profile/README.md`.
- **`install-gaming-mode.sh`** — Opt-in desktop Gaming Mode service, registered after Steam and Wallpaper Controller. Requires a live Quattro Hyprland session, systemd user session, Python, Steam, Gamescope and Wallpaper Controller. Installs missing dependencies through Omarchy, seeds the main monitor from the focused display once, deploys `gaming/gaming-mode.py` and `gaming/arch-gaming-mode.service`, and enables the service. Refuses foreign helper/unit files and backs up owned updates. Repeated installs report `already installed`; `--disable` stops/restores the mode, `--enable` reenables detection, and `--remove` additionally backs up/removes owned executable/unit while preserving configuration. No controller input permissions, scheduler, storage, Steam VDF or global game-launch-option changes. Automatically detects current-user Steam game processes (`SteamAppId`/`SteamGameId`), Lutris runner processes (`GAME_NAME`) and Steam game windows, so existing/new games launched from either client or Omarchy need no per-game edits. Big Picture/client windows alone no longer activate it. Known lingering Wine helpers, shader-precache workers and Wallpaper Engine are excluded. Detection stops the wallpaper using its supported CLI and enables main-monitor VRR, retaining resolution/HDR/scaling; after all detected games exit (three-second debounce), or on service stop, it restores VRR and the prior wallpaper if still owned. Also temporarily unloads the reviewed System Metrics, Weather and Immich overlays via supported Omarchy plugin controls; only originally enabled widgets are restored, with journaled crash/partial-failure recovery. Core/bar/lock IDs are refused, other plugins remain untouched, and no plugin source/pin is changed. `pausePlugins: []` opts out; a subset selects reviewed widgets. Shell IPC failures retain recovery state; the unit allows 120 seconds for orderly restoration. The widget-only tests found modest memory savings, not a graphics/FPS improvement. A version-1 same-session presentation hint now lets the separately pinned Shibumi bar stop decorative media animation without pausing playback (`pauseDecorations: false` opts out). Its controlled silent-MPRIS validation established a large shell-rendering reduction, not measured game FPS. `--prepare-benchmark` runs `gaming/prepare-cyberpunk-benchmark.py` to create a private hidden-HUD, per-frame CSV profile and proposed child-only prefix; it never launches/reconfigures a game, edits graphics settings or activates logging. Existing inherited HUD limiters must be audited before deliberate activation. The opt-in Gamescope launcher retains native resolution. See [Gaming Mode](gaming/README.md) for Guide-button setup, limitations, per-game launch options and verification.
- **`install-linuwux.sh`** — Optional shared LinUwUx and dedicated GE-Proton/UMU support, separate from game selection. Ensures `umu-launcher` and applies `gaming/denuvowo/configure.py` with SHA256-pinned assets. Requires x86-64 Linux, Python 3.12+, network/disk space on first install. Deploys owned launch helpers without changing boot/kernel, game profiles, shortcuts, saves or controllers. Preserves/refuses conflicting paths and privately backs up changed owned files. See `gaming/denuvowo/README.md`; disabled in the safe base.
- **`install-sunshine.sh`** — Installs Sunshine when missing; does not invent credentials, pair clients or configure capture/service policy. Doctor reports pending local service setup. Optional, not part of the safe base.
- **`install-tailscale.sh`** — Installs Tailscale and enables/starts `tailscaled` with system privileges. Existing package does not skip service reconciliation. Device enrollment remains an explicit authorization step; doctor checks running enrollment. Optional.
- **`install-keyd.sh`** — Installs keyd, privately backs up `/etc/keyd/default.conf`, deploys `keyd/default.conf`, enables/starts keyd and reloads changed configuration. Makes a system-wide key remap; optional, not selected by the safe base.
- **`install-zsh.sh`** — Installs Zsh when absent and uses `chsh` if it is not the user's default shell; may prompt for authorization. Selected by the personal/dotfiles profile, not required for the safe applications.
- **`install-dotfiles.sh`** — Stows only `nvim`, `starship`, `tmux`, `zsh` from the separate `${ARCH_SETUPS_DOTFILES_DIR:-../dotfiles}` checkout. Requires Stow and all packages, validated before the full run. Does not clone an unknown source or duplicate its configuration here. Simulates Stow, stages backups, tracks newly created paths and restores originals on failure/interruption. Preserves unrelated files and existing managed trees. Selected by the personal profile; use `--dotfiles-dir` for arbitrary clone/worktree locations.

## Desktop and plugin installers

All optional plugin controls and exact sources/pins are documented in [PLUGINS.md](PLUGINS.md). Direct successful no-argument invocation means install/re-enable; `--disable`/`--remove` remembers an opt-out. They do not modify package-owned Omarchy source. Removing a feature from this repository permanently also requires removing its script, explicit registration, registry/source-lock entries, shortcuts and documentation.

## Hyprland runtime helpers

- **`hypr/scripts/monitor-layout.py`** — Standard-library policy validator, resolver, geometry calculator and atomic deployer. Supports exact descriptions, explicit connectors or dynamic primary selection; roles/spans are optional rather than universally three-monitor. Rejects ambiguous identities, unsafe widget destinations and invalid numeric settings. Renders UTF-8 Lua without JSON-only escapes, retains the hyprmoncfg include last and restricts workspace overrides while the named-workspace toggle is active. Deployment CLI coordinates configuration writes with other setup helpers.
- **`hypr/scripts/monitor-mode-toggle.sh`** — Uses the deployed policy to keep/disable selected roles through a stateful `.lua` toggle. No connector-number assumption. Requires active Hyprland and configured keep output; restores multi-output mode by removing its owned toggle.
- **`hypr/scripts/window-span-dp6-dp4-toggle.sh`** — Historical filename only: resolves `windowSpan` roles at invocation, validates adjacent logical geometry, records original window position/size, and toggles the focused window between normal and two-output span. Requires two configured connected outputs; single-output policy reports that spanning is not configured.
- **`hypr/scripts/bar-visibility-mode-toggle.sh`** — Cycles Always show → Auto-hide → Disabled through user-state marker files and sends a notification. Does not restart the shell or use Hyprland `.conf` toggles.
